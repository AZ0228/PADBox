# PADBox

Read README.md and docs/architecture.md before implementation. Keep raw recordings, user collections, downloaded game data and icon dumps untracked. Use uv with Python 3.12+; run pytest and ruff for implementation changes. Preserve source/version provenance and unknown mechanics. New captures are isolated full-box snapshot drafts. Strong identity matches with clear copy tracking are accepted automatically within drafts; low-confidence matches and copy ambiguities require review. Only an explicit, current diff approval can replace the applied collection. Never append a rescan to current ownership. Preserve prior snapshots as immutable history. Inventory identity is per owned copy, never per monster ID. Preserve ambiguity in scroll tracking and across recordings. Synthetic fixtures are not evidence of real PAD recognition accuracy. Do not access authenticated game endpoints. `pool`, `shortlist`, and `check-team` may list candidates and check a named team. Keep the three team-building layers apart: `padbox.mechanics` interprets rules and never selects a team; `padbox.evaluator` (simulator in `padbox.evaluator.sim`) scores a supplied team and never searches; `padbox.optimizer` is the only layer that searches. Each layer has its own tests. Do not claim a team is optimal without a stated objective and search scope.
